## feat(mcp): 新增服务商无关的 MCP OAuth 客户端引擎（`5702ff5014dc`）

- Commit: `5702ff5014dcfef054f905b36d8f32c69f602ed5`
- 时间: `2026-10-27T16:15:43+08:00`

### 变更内容

新增 `tools/mcp/auth` 包，把 MCP 2025-06-18 授权规范的客户端侧协议一次性实现完：`ParseChallenge` 解析 401 的 `WWW-Authenticate`（含带逗号的 `error_description`）、`Discover` 读 RFC 9728 受保护资源元数据并跟随 issuer 取 RFC 8414 授权服务器元数据（401 不给 URL 时按 well-known 路径回退）、`Register` 做 RFC 7591 动态客户端注册、`NewPKCE`/`AuthorizeURL` 生成 S256 挑战与带 RFC 8707 `resource` 的授权地址、`Loopback` 监听一次性回调、`Exchange`/`Refresh`/`EnsureToken`/`Revoke` 管令牌生命周期、`Begin`+`Flow.Wait` 把上述串起来返回可直接持久化的 `Session`。同时导出 `Store` 接口与 `MemoryStore`、`ErrNoToken`/`ErrReauthRequired`/`ErrNotFound` 哨兵，以及 `OAuthError`、`RegistrationError` 两类可判别错误。

### 修改原因

下游接远程 MCP 目前只有静态 header 一条路，遇到要求 OAuth 的服务商就得在应用里重写一遍发现+注册+PKCE+回调，而各家规范实现参差（是否支持 DCR、是否只接受机密客户端、是否回 `iss`），重复实现会把服务商特例固化进调用方。协议层进框架后，调用方只需要负责它真正独有的部分：注入 Bearer、持久化会话、打开系统浏览器。

### 实现方式

包内不引入 transport、不假设存储位置、不开浏览器，也不写任何服务商分支——具体服务只以元数据形式进入。客户端凭据完全由元数据与注册结果决定：`token_endpoint_auth_methods_supported` 声明 `none` 时公开客户端优先 `none`（配 PKCE），只声明 basic/post 时 DCR 直接请求 `client_secret_basic` 并使用注册响应下发的 `client_secret`，用户手工登记凭据时按同样规则选路且跳过 DCR；没有 `registration_endpoint` 则返回携带 loopback 回调地址的 `RegistrationError`，把"去服务商加白回调"这一步交给调用方的文案。安全边界集中实现：远端端点强制 HTTPS（仅 `127.0.0.1`/`localhost` 允许 HTTP），`ensureHTTPClient` 克隆调用方 client 后再挂同一套重定向校验，回调只监听 127.0.0.1、单次消费、state 用 `subtle.ConstantTimeCompare` 比较、回调带 `iss` 时与 issuer 比对，错误串只含状态码与 OAuth 错误码，不外泄 token/code/secret。`Refresh` 把 `invalid_grant`（refresh token 失效或已被别处轮换）用双 `%w` 包成 `ErrReauthRequired`，调用方 `errors.Is` 判"要重新授权"、`errors.As` 仍能取回原始 `*OAuthError`；服务端未回 `refresh_token` 时保留旧值，避免轮换失败直接丢会话。测试用 `httptest` 假授权服务器覆盖发现（含 issuer 不匹配、非 loopback http 拒绝）、DCR 与手工 client、机密客户端 basic 选路与凭据误用被拒、PKCE 交换、state 不匹配不换 token、回调错误映射、刷新与 `invalid_grant` 归类、撤销、`MemoryStore`，全程不访问真实网络；`-race -count` 连续通过。
