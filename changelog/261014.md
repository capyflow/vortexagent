## fix(agent): Wait 容忍任务在解析之后被淘汰（`5ef99da0f629`）

- Commit: `5ef99da0f629223a66ced3bf5a1e81a9e3d82af6`
- 时间: `2026-10-14T16:38:20+08:00`

### 变更内容

TaskHub.Wait 在解析出任务 ID 列表后，若某个 ID 已不在任务表中，不再报"任务 xxx 不存在"，而是视为已等待完成。

### 修改原因

Wait 先加锁解析 ID，再逐个 Status 取 done 通道；pruneLocked 只淘汰已进终态的任务，因此列表中的任务可能在两次加锁之间结束并被清理，形成假的失败返回。此前会话回滚使各任务耗时几乎恒定，窗口被掩盖；"轮数耗尽不回滚"落地后历史变长、完成时序分散，TestTaskHub_HistoryPruned 在 `-race` 下必现该失败。

### 实现方式

只改判定：解析后查不到即等同终态已达成（因为淘汰的前置条件就是终态），不改变 Wait 的返回值形状与 ctx 取消语义。回归由既有的 TestTaskHub_HistoryPruned 覆盖（修复前三次 `-race` 必失败，修复后连续通过）。

### 涉及文件

- `agent/taskhub.go`

## feat(agent): 轮数上限支持按次设置，耗尽不再回滚会话（`ff3eb3692196`）

- Commit: `ff3eb3692196ec8d27c348439516e2d0355c4a62`
- 时间: `2026-10-14T16:38:07+08:00`

### 变更内容

新增 `WithMaxIterations(n)` AskOption，单次提问可覆盖 `Options.MaxIterations`；工具轮数耗尽时不再回滚会话历史，错误改为可识别的导出哨兵 `ErrIterationLimit`。

### 修改原因

`MaxIterations` 原本是 Agent 级配置，逐步推进的长程执行器（计划/目标）需要按次放宽上限，否则只能为不同上限各建一个 Agent 实例。另一半是正确性问题：耗尽时 `session.Rollback(baseLen)` 会抹掉整轮推理与工具结果，而这些副作用（写文件、执行命令）本就无法撤销，回滚只留下"副作用已发生、记录消失"的失真历史，调用方也无从续跑。

### 实现方式

`askConfig` 加 `maxIter`，循环上限取 `cfg.maxIter > 0 ? cfg.maxIter : a.maxIter`（n<=0 保持沿用 Agent 默认）；耗尽分支用 `%w` 包装 `ErrIterationLimit` 并保留历史。其余失败路径（ctx 取消、调用失败、空回答、工具循环取消）的回滚语义保持不变，Ask 顶部"失败时历史回滚到提问前"的文档注释同步更正。

### 涉及文件

- `agent/ask.go`
- `agent/iteration_limit_test.go`

## feat(llm): 流式请求主动索取 token 用量（`941d5c4c2c05`）

- Commit: `941d5c4c2c056a1de0af1c4240a9a4dcb654301d`
- 时间: `2026-10-14T16:37:54+08:00`

### 变更内容

`stream=true` 时在请求体带上 `stream_options:{"include_usage":true}`，并新增 `llm.WithStreamUsage(bool)` 与 `ProviderConfig.StreamUsage` 作为关断门（nil 视为开启）。

### 修改原因

OpenAI 兼容网关默认不在流中回传 usage，需要显式索取才会在末片给出；解析侧（`readStream` 收 `chunk.Usage`、`parseUsage` 映射缓存字段）本已支持，只差请求侧。此前依赖 `OnLLMCall` 做 token 统计的调用方在流式路径上恒得 0，成本观测建立在假数据上。

### 实现方式

wire 请求结构加可选 `StreamOptions`，仅在 `streaming && p.streamUsage` 时置位，非流式不发；提供关断门是因为个别严格网关会因这个未知字段返回 400。测试用 `httptest` 起 mock SSE 服务端，断言默认携带该字段、末片 usage 解析出输入/输出/缓存读、关断后不发、非流式不发，以及工厂路径的三档透传。

### 涉及文件

- `llm/openai.go`
- `llm/protocol.go`
- `llm/openai_stream_usage_test.go`

## test(llm): 回归用例不再使用 go1.24 的 t.Context()（`afbbcec91d21`）

- Commit: `afbbcec91d212a59042916c295f33970f126cad7`
- 时间: `2026-10-14T16:37:36+08:00`

### 变更内容

`llm/openai_nullargs_test.go` 用 `context.Background()` 取代 `t.Context()`。

### 修改原因

本模块 `go.mod` 声明 `go 1.23`，而 `t.Context()` 是 go1.24 才加入的测试 API，语言版本门控使 `go vet ./...` 与 `go test ./llm` 在声明的工具链下直接编译失败——包内其它测试因此无法运行。

### 实现方式

只替换 ctx 来源，测试语义不变（httptest 服务由 defer 关闭，不依赖测试结束时的自动取消）。若上游更希望保留 `t.Context()`，应改为把 `go.mod` 的语言版本升到 1.24 并同步下游最低工具链要求。

### 涉及文件

- `llm/openai_nullargs_test.go`
