## fix: filesystem 路径校验在符号链接根目录下误报越界（`36a5d7922b6a`）

- Commit: `36a5d7922b6a33c3edeb63aed038dd64ce0ffa30`
- 时间: `2026-09-29T18:32:52+08:00`

### 变更内容

tools/filesystem 的 safeResolve 路径边界校验，修复 rootDir 位于符号链接路径之下时（如 macOS /var → /private/var，测试的 t.TempDir() 即此形态）所有相对路径读取被误报"路径越界"的问题。

### 修改原因

第一层校验拿"符号链接解析后的根目录"比较"未解析的目标路径"，两者基准不一致必然失配；该包全部测试在 macOS 环境因此失败。

### 实现方式

改为两层各自成对的比较——先用未解析根与未解析目标比较，再对 EvalSymlinks 解析后的真实路径与真实根做二次校验；目录穿越与符号链接逃逸的防护语义不变。

### 涉及文件

- `tools/filesystem/filesystem.go`

## feat: 工具输出源头节流 — exec/filesystem 结果进历史前截断（`41909ee5dfa9`）

- Commit: `41909ee5dfa96b8d29e3da66cb243f49d719a82f`
- 时间: `2026-09-29T18:33:54+08:00`

### 变更内容

exec_command 的命令输出与 read_file 的文件内容在进入会话历史前按字符上限截断，并标注原始长度；新增 tools.exec.maxOutput / tools.filesystem.maxContent 配置（0/未配置取默认 8000，-1 不限制）。

### 修改原因

工具结果占每轮上下文增量的绝大部分（对话文本仅约 4%），一次大文件读取或长命令输出即可显著推高上下文；治理上下文膨胀必须从源头节流，而非只在组装端压缩。

### 实现方式

ExecTool/ReadFileTool 增加 WithMaxOutput/WithMaxContent 选项，按 rune 边界截断并追加"完整输出共 N 字符"标注（提示完整内容可经归档回读）；截断只作用于进入历史的结果文本，不影响命令执行与文件读取本身的语义；默认即生效，无需配置。

## feat: ctxengine 单会话上下文引擎 — 长会话上下文不再线性膨胀（`6dd57a50f0f7`）

- Commit: `6dd57a50f0f77b402fe4aa5f0ffdb89b69880f99`
- 时间: `2026-09-29T18:34:25+08:00`

### 变更内容

新增 ctxengine 包（单会话上下文引擎）：活跃上下文 = 摘要区 + 最近块原文 + 按需检索片段，原始历史不可变归档；替换并删除旧 ContextManager/OffloadStore 死代码子系统；vortex 与 vortex-serve 经 config.context 启用；docs/context.md 完整说明三种上下文组件（ctxengine/memory/knowledge）。

### 修改原因

每轮 Ask 发送完整历史使上下文随对话轮数线性膨胀，长会话必然超窗；旧 ContextManager 为零调用的死代码且存在构造绑定固定 Session（与 serve/TaskHub 不兼容）、offloadStore 为 nil 时仍替换历史（丢原文）、PG 不持久化卸载块、摘要失败静默降级等缺陷。

### 实现方式

块模型（相邻用户消息之间的全部消息）保证 tool_calls 与结果结构上不拆散；四层防线（预算组装 / 发送前硬校验 / usage 校准 / 超窗裁剪重试）；轮末异步归档流水线——原文先落库（指纹去重，崩溃与重试幂等）再一次 LLM 双输出{状态交接摘要, 候选事实}，摘要失败不卸载、原文零丢失；候选事实以低置信 + Source 标记写入长期记忆，显式 memory_save 仍是主通道；归档对模型只读，生命周期 retentionDays 管理；检索纯被动（search_history/expand_chunk，会话经 context 注入，CLI 与 serve 零额外接线）；引擎不绑定 Session 指针，同一实例服务 REPL/serve 多会话/subagent；Summary 区超预算自动合并为 global 摘要；源头节流配置接线至两入口。
